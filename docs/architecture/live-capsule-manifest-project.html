Builder architecture · 2026-07-16

Live Capsule Manifest project

Capsule is a live, editable Manifest project — not a detached assembled artifact. Domain changes happen in Capsule-owned .manifest files and manifest.config.yaml, then Builder regenerates only Builder-owned output.

initial copy source + generate update compile from Capsule migrate import without regen no implicit Convex deploy
01

Correction

Before: regenerate from an external IR dump. After: Capsule owns the editable source of truth.

Detached artifact (wrong)

  • IR read from Manifest-source/generated/ir
  • Capsule held only projections + app glue
  • Domain edits required the external repo forever
  • Config/naming lived outside the app

Live Manifest project (required)

  • Editable .manifest + config live inside Capsule
  • Update compiles from Capsule only
  • Generated Convex/runtime files stay Builder-owned
  • UI/auth/env remain Capsule-owned

04

Commands

Dry-run by default. Capsule is not modified unless --apply is explicit.

Initial
once
npm run project:generate:convex -- --mode initial --manifest-source <dir> --target <Capsule> --apply

Copies editable Manifest files into the target, compiles from those copies, writes generated ownership separately.

Update
ongoing
npm run project:generate:convex -- --mode update --target <Capsule> --apply

Compiles from Capsule’s own Manifest tree. No Manifest-source dependency. Conflicts on modified generated files.

Migrate
explicit
npm run project:migrate:manifest-source -- --from <Manifest-source> --target <Capsule> --apply

Imports editable source/config into an existing Capsule without regenerating projections or overwriting app work.
