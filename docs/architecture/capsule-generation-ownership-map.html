Capsule generation ownership map

Machine-readable ownership in .builder/ownership.json separates Capsule-editable Manifest inputs from Builder-generated digests.

Four lanes

Lane A
Editable Manifest
  • *.manifest
  • manifest.config.yaml|yml|ts
  • Recorded in editableManifest.paths
  • Never hashed as generated
Lane B
Builder generated
  • convex/* projections
  • wiring / zod / contract-tests
  • SHA-256 in files
  • Conflict if hand-edited
Lane C
Application owned
  • UI, routes, customization
  • Auth/crypto seams after customize
  • Extra package scripts/deps
  • Preserved on update
Lane D
Protected state
  • .env*
  • .convex/
  • Lockfiles
  • Never claimable / never auto-deploy

Update decision flow

1. Load Capsule Manifest

Read in-project .manifest + config. Compile via Manifest public APIs. External Manifest-source is unused.

→

2. Assemble generated set

resolveProjectionOptions applies naming/aliases/storage maps. Preset emits only Lane B files.

→

3. Plan with ownership

Add/modify/delete only unchanged generated digests. Editable + app + protected paths are skipped or conflicted.

ownership.json shape

Field Owner Update behavior
files Builder Replace when digest still matches; conflict when modified
package Builder requirements Structural merge; app-only entries survive
editableManifest Capsule Preserved; never written from generated output
