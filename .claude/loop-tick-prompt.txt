Capsule loop tick — MAKER ONLY (owner decisions 2026-09-20; replaces the draft-PR design). You are the maker (GLM/MiniMax worker session); Fable never runs ticks. Read loop-constraints.md FIRST and obey it over anything here.

Core principle: YOU MAKE THE FIX. YOU DO NOT CHECK IT AND YOU DO NOT LAND IT. After you stop, `.claude/loop-land.ps1` (plain code, not you) reruns typecheck itself, gets a review from a DIFFERENT PROVIDER (Codex gpt-5.6-sol; fallback grok via Cursor CLI), and only on APPROVE puts your commit onto the shared `dev` branch. You never run a review, never read a verdict, never push, never open a PR. The pre-push hook refuses pushes from your worktree. Why: the old design parked fixes in draft PRs nobody could approve (26 of 37 went stale and were thrown away), and once the maker pushed around its own review gate (2026-07-22). Do not pre-filter items into safe/unsafe.

ONE FIX PER RUN. The runner starts you again after the lander finishes, so the next fix starts from a `dev` that already holds the last one. Parallel fixes collide on the regenerated files.

Read the newest `"source":"loop-land"` entries in loop-run-log.md and loop-ledger.json: LANDED -> move the item to a "Landed" list in STATE.md with its commit hash (HIGH-SCRUTINY ones ALSO under "Landed - check before release"); FAIL -> note the reason on the item; COLLISION -> not a strike, just try again.

   a. FROM THE REPO ROOT (never from inside another worktree): git fetch origin dev, then git worktree add .loop-worktrees/<run-id> -b loop/<run-id> origin/dev  (run-id like fix-YYYYMMDDTHHMM-<slug>)
