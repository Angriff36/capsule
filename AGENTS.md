# CapsuleX — agent instructions

Canonical instruction file for automated contributors. Prefer this over scattered notes.

## Purpose

CapsuleX is a catering / event operations app: Vite + React frontend, Convex backend, Clerk auth, assembled from Manifest (`@angriff36/manifest`) proofs.

## Authoritative directories

| Path | Role |
| --- | --- |
| `src/` | Shipping UI (authored). Prefer feature folders under `src/features/`. |
| `convex/` | Convex backend. Mix of generated surfaces and author-owned seams. |
| `convex/lib/` | Author-owned Convex helpers (`authContext`, encryption). |
| `convex/_generated/` | Generated by Convex — do not edit. |
| `src/generated/`, `src/lib/manifest-convex-react.ts` | Manifest-generated client wiring — do not edit by hand. |
| `schemas/`, `wiring/`, `scripts/seed-convex.ts` | Manifest assembly outputs — regenerate, do not hand-patch. |
| `tests/` | Vitest suite (policy unit tests + generated contract tests). |
| `diagrams/` | Manifest docs/diagrams companion. |
| `.artifacts/` | Ignored scratch/diagnostics only. |
| `graphify-out/` | Ignored graphify knowledge-graph output. |

Shipping application root is this repository (not a monorepo).

## Commands agents may run

```bash
bun install --frozen-lockfile
bun run dev              # Vite on http://localhost:7811
bun run dev:convex       # Convex local/dev sync
bun run typecheck
bun run lint
bun run test
bun run build
bun run secrets
bun run check            # typecheck + lint + secrets + test + build
bun run codegen          # convex codegen
bun run seed             # seed script (requires Convex URL)
```

## Required validation gates

Before claiming work complete, `bun run check` must pass.

CI runs the same `check` script.

## Generated-code rules

- Never hand-edit Manifest/Convex generated files listed above.
- Regenerate with Manifest Builder / `bun run codegen` from authoritative sources.
- Import Convex API through `src/lib/api.ts` for app code.
- If regeneration would overwrite author seams, stop and preserve `convex/lib/**`, `convex/auth.config.ts`, and `convex/authStatus.ts`.

## Secret handling

- Real secrets live in `.env.local` (ignored) or Convex/Clerk dashboards.
- Use `.env.example` as the contract; never commit secret values.
- `bun run secrets` must stay green; it self-tests against `tests/fixtures/secret-scan/synthetic-leak.txt`.

## Commit expectations

- One concern per commit; include proof (`bun run check` or the focused subset).
- Do not commit `.env.local`, credentials, or `.artifacts/` dumps.
- Do not amend pushed history or force-push `main`.

## Prohibited actions

- Do not weaken TypeScript strictness or delete failing tests to go green.
- Do not add tools that are not wired into `bun run check` / CI.
- Do not invent a second package manager lockfile (`package-lock.json` is rejected).
- Do not start feature work by rewriting Manifest-generated backend surfaces.

## Temporary outputs

Put diagnostics, reports, and scratch files under `.artifacts/` (gitignored).
