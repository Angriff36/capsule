CapsuleX is a full catering / event-operations SaaS that lets a catering business owner organize and connect every moving part of their operation — events, clients, dishes, recipes, ingredients, inventory, equipment, staff, vehicles, vendors, schedules, invoices, and payroll — and build meaningful automations between them. The product's central idea is relational: adding a fully-specified event (client, headcount, selected dishes) automatically derives its prep lists, multiplies recipe ingredients by headcount to compute ingredient demand, aggregates demand across all of a week's events into a consolidated purchasing/ordering form, and cascades downstream into production batches, pack lists, deliveries, staff assignments, closeouts, and invoices. Architecturally, CapsuleX is a generated application. Domain behavior is authored in the Manifest DSL (`@angriff36/manifest`) as `.manifest` files describing entities, enums, state-machine transitions, commands (with guards/constraints/mutations), events, reactions/fan-outs, and computed aggregates. The Manifest Builder compiles these proofs into a Convex backend (schema, queries, mutations, crons, HTTP endpoints, sagas, computed values) plus React client wiring. The authored surface is limited to the React UI (`src/features/**`, `src/app/**`, `src/ui/**`), Convex author seams (`convex/lib/**`, auth config), and an agent command bridge (MCP → Convex). Frontend is React 18 + Vite + Tailwind, the data plane is Convex, and identity/org-membership is handled by Clerk. Multi-tenancy is pervasive (every entity is TenantScoped/SoftDeletable). The repo enforces a strict generation boundary: generated trees are never hand-edited, and all schema/behavior changes flow through `bun run manifest:regen`.
